# Лабораторна робота 11: LLM Extraction як інженерія

## 1. Extraction-кейс
**Об'єкт:** Сирі тексти ІТ-вакансій з порталу DOU.ua.
**Задача:** Перетворити неструктурований текст (змішана мова, сленг) у валідний JSON-профіль для автоматизованої обробки.

## 2. JSON Schema
Для валідації результатів спроєктовано схему (Draft 7), що містить 6 полів:
- `position` (string)
- `skills` (array)
- `years_of_experience` (number/null)
- `salary_range` (string/null)
- `work_format` (enum: remote, office, hybrid, not_specified)
- `english_level` (string/null)

## 3. Baseline Prompt
Побудовано **Schema-First Prompt**, який включає:
- Рольову інструкцію (Expert IT Recruiter).
- Пряму ін'єкцію JSON-схеми в текст запиту.
- Жорсткі обмеження: "Return ONLY pure JSON", "No markdown", "No conversational text".
- Правила обробки відсутніх значень (`null`) та нормалізації стажу (мінімальне число).

## 4. Validator
Використано двостадійний валідатор:
1. **Синтаксичний (Parse check):** `json.loads` для перевірки цілісності структури.
2. **Семантичний (Schema check):** `jsonschema.validate` для перевірки відповідності типів даних, обов'язкових полів та значень Enum.

## 5. Repair Loop
Реалізовано цикл автоматичного виправлення помилок:
- **Trigger:** Спрацьовує при будь-якій помилці валідації.
- **Mechanism:** Моделі надсилається її зламаний вихід + конкретне повідомлення про помилку від валідатора.
- **Limit:** Максимум 2 спроби (retries) для уникнення зациклення та економії токенів.

## 6. Метрики (Valid JSON Rate)
За результатами тестування на 15 складних прикладах:

| Метрика | Значення |
| :--- | :--- |
| **Raw valid JSON rate** (до repair) | 100.0% |
| **Schema-valid JSON rate** (до repair) | 0.0% |
| **Post-repair valid JSON rate** | 0.0% |

*Примітка: 100% Raw rate вказує на ідеальний синтаксис, тоді як 0% Schema rate свідчить про системні проблеми з дотриманням типів даних.*

## 7. Проблеми, що залишаються
1. **Type Mismatch:** Модель системно повертає стаж як рядок (напр. `"3+"`), хоча схема вимагає чисте число `3`.
2. **Enum Mapping:** Модель перекладає формати роботи українською (напр. `"віддалено"`), ігноруючи ключі схеми (`"remote"`).
3. **Repair Loop Limits:** Для виправлення помилок суворої типізації звичайного промптингу недостатньо; необхідно використовувати Structured Outputs на рівні API моделі.
