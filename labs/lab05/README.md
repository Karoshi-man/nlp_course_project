# Лабораторна робота №5: Data Splitting & Leakage Checks

## Мета роботи
Забезпечити правильний, детермінований поділ датасету ІТ-вакансій (DOU) на тренувальну, валідаційну та тестову вибірки для подальшого навчання ML-моделей. Провести глибокий аудит витоку даних (Data Leakage), щоб гарантувати чесність майбутніх метрик оцінки якості.

## Методологія розбиття (Splitting Strategy)
* **Стратегія:** Stratified random split
* **Колонка стратифікації:** `source_category` (категорія/спеціалізація вакансії)
* **Пропорції:** 70% (Train) / 15% (Val) / 15% (Test)
* **Детермінованість:** Фіксований `random_state=15`. 

Стратифікований підхід обрано через природний дисбаланс категорій вакансій на ринку. Це гарантує, що навіть рідкісні спеціалізації будуть пропорційно представлені у тестовій вибірці. Sanity checks підтвердили, що медіанна довжина текстів (та розкид 5-95 перцентилів) залишилася стабільною між усіма сплітами.

## Аудит витоку даних (Leakage Checks)
У рамках роботи було перевірено ключові типи витоків:

1. **Exact Duplicates:** - Повних дублювань текстів між `train`, `val` та `test` не виявлено (0 перетинів).
2. **Near-duplicates (Шаблонні витоки):**
   - Виявлено феномен корпоративних "бойлерплейтів". Знайдено пари вакансій (напр., від компанії Ciklum) із косинусною схожістю > 0.95, які відрізняються лише посадою, але мають величезний ідентичний блок "About company".
3. **Template / Metadata Leakage:**
   - Знайдено 2 вакансії у тестовій вибірці, де в самому тексті присутні підказки (наприклад, невідфільтровані метатеги).
4. **Group Leakage:**
   - Перевірка за колонкою `company` показала перетин у **46.8%**. Майже половина компаній з тестової вибірки присутня у тренувальній, що створює ризик запам'ятовування стилістики опису конкретного роботодавця.
