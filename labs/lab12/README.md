# Лабораторна робота №12 — Tool-grounded Single-Agent

### 1. Опис Use Case
Метою роботи є створення **Vacancy Assistant** — агента, який аналізує тексти IT-вакансій (наприклад, з платформи DOU) і автоматично витягує з них ключову інформацію: стек технологій та мінімально необхідні роки досвіду.

### 2. Архітектура та Інструменти (Tools)
Система побудована за архітектурою ReAct (Reason + Act). Замість того, щоб покладатися виключно на знання моделі, агент використовує детерміновані Python-функції (інструменти) для точного пошуку даних. Усі виклики суворо фіксуються через `ToolLogger` у файл `tool_logs_lab12.jsonl`.

Реалізовано 2 інструменти:
1. `extract_technologies`: Використовує словник для пошуку мов програмування та фреймворків (Python, AWS, React тощо).
2. `detect_experience_years`: Використовує регулярні вирази для розпізнавання необхідного досвіду (наприклад, "3+ роки", "від 1 року").

### 3. Базові Метрики (на 10 Test Cases)
* **Tool call success rate:** 100.0% (усі функції Python відпрацювали без системних збоїв).
* **Average tool calls per task:** ~2.0 (Агент системно викликав обидва інструменти для повноти картини).
* **Відсоток задач із корисними викликами:** 80% (успішно витягнуто дані з IT-вакансій).
* **Зайві виклики (Unnecessary calls):** 20% (Агент викликав інструменти для нетехнічних вакансій або описів без вимог, наприклад, для "Sales Manager").

### 4. Аналіз Baseline vs. Agent
Базова модель (Baseline LLM), аналізуючи вакансії, часто піддавалася галюцинаціям: якщо у тексті не був вказаний досвід, модель могла сама придумати "стандартний 1 рік". 
Tool-grounded Agent повністю усунув цю проблему. Отримуючи від інструменту `null`, агент чесно відповідав: "досвід роботи не вказано". Крім того, агент зміг коректно обробити вакансії з конфліктним досвідом ("від 1 року, але ідеально 3+"), спираючись на масив даних від регулярних виразів.

### 5. Головний висновок та напрямки покращення
Агентний підхід робить екстракцію даних з вакансій набагато надійнішою. Головна точка для покращення — навчити агента стратегії "Early Exit". Для цього потрібно додати інструмент-класифікатор (наприклад, `is_tech_vacancy`), і якщо вакансія виявиться нетехнічною (Sales, HR), агент повинен припиняти роботу без марного виклику екстракторів технологій.
