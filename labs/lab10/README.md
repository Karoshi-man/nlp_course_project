# Lab 10: NER Pipeline + Hybrid Rules (DOU Vacancies)

## 1. Який корпус та Evaluation Set використано
У роботі використано корпус ІТ-вакансій з платформи DOU (583 документи після фільтрації коротких текстів). Для швидкого та якісного тестування NER-системи було створено напівручний **Evaluation Set із 15 речень**, які репрезентують найскладніші доменні кейси (мікс українського тексту, англійського ІТ-сленгу, спецсимволів та зарплатних вилок).

## 2. Який pipeline запущено
Базовим пайплайном обрано **spaCy** з англомовною статистичною моделлю `en_core_web_sm` (оскільки більшість ІТ-навичок пишуться англійською). Для побудови гібридного шару використано компонент `EntityRuler`.

## 3. Які rules додано
Додано 3 типи гібридних правил, що перекривають сліпі зони базової моделі:
1. **Exact Match Словник (`TECH`):** Перелік ключових технологій (Python, React, AWS, Docker, CI/CD тощо).
2. **Token Regex (`EXPERIENCE`):** Патерн для гнучкого пошуку досвіду (`[число] + [опціональний +] + [years/роки]`).
3. **Boundary format (`MONEY`):** RegEx-подібні структурні правила для типових ІТ-зарплат (наприклад, `$4k` або `3000 - 4500 USD`).

## 4. Що baseline знаходив добре
Базова модель (без правил) успішно знаходила лише класичні "міжнародні" сутності, на яких вона тренувалася в новинах:
* Великі відомі компанії (`ORG`: Epam, GlobalLogic).
* Локації (`GPE`: Kyiv).

## 5. Що baseline пропускав (або плутав)
* **Пропуски:** Повністю ігнорував бази даних (PostgreSQL, MongoDB) та вимоги до досвіду роботи.
* **Помилки типу (Type Errors):** Плутав технології з людьми чи локаціями (наприклад, "Java" та "C++" розпізнавались як `PERSON`, а "React" як `GPE`).
* **Помилки меж (Boundary Errors):** Розбивав сутності зі спецсимволами (витягував лише "CI" з "CI/CD") або "відкушував" знаки валют від цифр.

## 6. Що rules покращили
Гібридні правила кардинально змінили ситуацію:
* Кількість правильно знайдених сутностей (Exact Match) на нашому тестовому наборі зросла з **2 до 33**.
* Правила повністю прибрали галюцинації (Type Errors) для технологій, перекривши їх лейблом `TECH`.
* Досвід роботи тепер витягується ідеально, незалежно від мови написання.

## 7. Які проблеми ще не вирішені
* **Невідомі організації:** Якщо назва ІТ-компанії дуже рідкісна або пишеться незвично, базова модель її пропускає. Це вимагає донавчання моделі (Train NER), а не просто правил.
* **Сліплезна токенізація:** Якщо автор вакансії написав технології через слеш без пробілів (`Python/Django/PostgreSQL`), точний словниковий збіг може дати збій через особливості базового токенізатора spaCy.
