## 1. Модель і параметри
* **LSA (Latent Semantic Analysis):** `TfidfVectorizer` + `TruncatedSVD`.
* **LDA (Latent Dirichlet Allocation):** `CountVectorizer` + `LatentDirichletAllocation`.
* **Параметри векторизаторів (для обох моделей):** `min_df=5`, `max_df=0.90`, `stop_words='english'`.
* **Кількість тем (k):** Протестовано для $k=5$ та $k=8$. Тексти попередньо відфільтровані (залишено речення $\ge 4$ слів).

## 3. Аналіз "поганих" тем

**Погана тема 1: "Stop-word / Template topic" (LSA Тема #1 / LDA Тема #3)**
* **Топ-слова:** `та`, `для`, `на`, `досвід`, `роботи`, `ми`, `даних`, `до`, `або`, `що`.
* **Чому вона погана:** Алгоритм просто згрупував українські прийменники та шаблонні фрази вакансій ("досвід роботи", "ми шукаємо"). Це відбулося через те, що параметр `stop_words='english'` очистив лише англійський шум, залишивши український.
* **Що б ми змінили:** Створити кастомний масив українських стоп-слів та передати його у векторизатори. Перевести текст у `lemma_text` для зменшення кількості слоформ.

**Погана тема 2: "Mixed / Too generic topic" (LSA Тема #0)**
* **Топ-слова:** `та`, `data`, `experience`, `ai`, `для`, `team`, `python`, `work`, `на`, `ml`.
* **Чому вона погана:** Тема намагається поєднати непоєднуване (українські прийменники, загальні корпоративні слова та конкретні навички). Це стається, коли $k$ занадто мале, і алгоритм "скидає" залишковий шум в один великий кластер.
* **Що б ми змінили:** Збільшити кількість тем (наприклад, $k=10$). Жорсткіше обмежити `max_df` (наприклад, до 0.6 або 0.7), щоб відсіяти всюдисущі слова на кшталт `experience` та `team`.

## 4. Порівняння LSA vs LDA
* **Читабельність:** LDA виявилася значно читабельнішою для корпусу коротких речень з вакансій. Вона формує цілісні "ролі" (профілі посад), тоді як LSA видає жорсткі, хоч і точні, "словникові теги".
* **Шум та Дублікати:** У LSA виявилося більше структурного шуму (змішаних тем), оскільки через свою ортогональність алгоритм намагався жорстко розбити двомовний датасет за мовною ознакою. Натомість LDA має дещо більше схожих/дубльованих тем через свій імовірнісний підхід до розподілу загальних слів (типу `work`, `experience`).
* **Висновок для DOU:** Імовірнісна природа LDA краще підходить для коротких текстів вакансій, де навички часто переплітаються з описом компанії та soft skills.

## 5. Висновок
Тематичне моделювання ефективно знаходить приховані сюжети (ML, Data Engineering, Backend) у нерозмічених текстах вакансій DOU. Проте експерименти підтвердили, що якість тем критично залежить від препроцесингу. Двомовність датасету вимагає обов'язкового налаштування кастомних стоп-слів для обох мов, інакше моделі витрачають ресурс на виділення мовного стилю, а не бізнес-змісту. Ручна інтерпретація топ-документів довела свою незамінність, дозволивши вчасно виявити шумні та "сміттєві" кластери, які могли б мати високі автоматичні метрики (Coherence) суто через часту сумісність прийменників.
