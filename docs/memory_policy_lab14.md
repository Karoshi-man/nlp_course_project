# Memory & Knowledge Policy (Lab 14)

**1. Що зберігається в state**
У `FlowState` зберігаються лише дані, що стосуються поточного кейсу (task_id): сирий текст, очищений текст, присвоєний маршрут, сирі виводи від LLM (`extracted_data`), результати валідації та статуси помилок.

**2. Що не зберігається**
Не зберігається історія попередніх вакансій (Flow є stateless між різними запусками). Не зберігаються ваги моделей або конфігурації підключення до LLM всередині стану кейсу.

**3. Які intermediate outputs можуть передаватися між етапами**
Етап `Execute` передає згенерований словник у `state.extracted_data`. Етап `Validate` не змінює ці дані, але створює об'єкт `state.validation_result`, який читає етап `Fallback` для прийняття рішень.

**4. Як логуються помилки**
Помилки не викликають `Exception` у головному потоці. Вони акумулюються у масиві `state.errors` (для критичних збоїв, як-от JSONDecodeError) та `state.warnings` (для логічних підозр). Ці масиви долучаються до фінального експорту.

**5. Як працює knowledge / schema registry**
Всі схеми (наприклад, `TECH_VACANCY_SCHEMA`) та довідники існують як константи в окремому файлі `src/schemas.py`. Етапи Flow лише імпортують їх для використання.

**6. Які файли є read-only knowledge**
* `TECH_VACANCY_SCHEMA` (сувора JSON-схема вимог).
* `TECH_KEYWORDS` (список слів для роутингу).
* `NON_TECH_KEYWORDS` (список слів для відхилення вакансій).

**7. Як запобігається state pollution**
Для кожної нової вакансії створюється абсолютно новий екземпляр класу `FlowState(raw_text)`. Змінні не "перетікають" між різними вакансіями. Якщо етап `validate` бракує дані, вони позначаються невалідними, і Fallback може їх перезаписати.

**8. Які дані не можна логувати**
У логах (`flow_logs_lab14.jsonl`) заборонено зберігати конфіденційні дані кандидатів або рекрутерів (номери телефонів, email), якщо вони випадково потрапили в текст вакансії, а також API-ключі або системні шляхи локальної машини.
