# Flow Notes Lab 14: Vacancy Assistant

**1. Який use case обрано**
Аналіз та структурування IT-вакансій з платформи DOU (витягування стеку технологій та років досвіду).

**2. Які етапи flow**
1. `ingest` (прийом та очищення тексту).
2. `route` (визначення технічної чи нетехнічної вакансії).
3. `execute` (виклик локальної LLM Llama-3 для екстракції даних).
4. `validate` (перевірка JSON-схеми та логіки значень).
5. `apply_fallback` (відновлення даних через RegEx у разі помилок).
6. `export` (формування фінального JSON).

**3. Яка структура state**
Об'єкт `FlowState` містить: `case_id`, `raw_text`, `clean_text`, `route`, `routing_reason`, `extracted_data`, `validation_result`, `fallback_triggered`, `fallback_result`, `status`, масиви `errors` та `warnings`, і фінальний `final_output`.

**4. Які routes можливі**
* `tech_extraction` (для IT-вакансій, потребує виклику LLM).
* `non_tech_skip` (для HR/Sales вакансій, пропускає виклик LLM).
* `unknown` (для спаму або незрозумілих текстів).

**5. Що робить execute**
Формує prompt із суворим запитом на JSON-формат, викликає локальну модель (`unsloth/llama-3`), парсить її відповідь і записує результат у `state.extracted_data`.

**6. Що перевіряє validate**
Перевіряє, чи відповідає `extracted_data` структурі `TECH_VACANCY_SCHEMA` (за допомогою бібліотеки `jsonschema`). Також містить кастомну логіку: якщо `experience_years` > 20 або < 0, кидає попередження (Warning).

**7. Коли спрацьовує fallback**
Якщо етап `execute` завершився падінням (наприклад, LLM не змогла згенерувати валідний JSON) або етап `validate` повернув `schema_ok: False`. Fallback намагається знайти роки досвіду звичайним RegEx, щоб врятувати хоч якісь дані.

**8. Який export format**
Стабільний JSON, що гарантовано містить поля: `case_id`, `route`, `final_output` (словник з даними або null), `needs_manual_review` (boolean), `status`, `warnings`, `errors`.

**9. Що flow покращив порівняно з ad-hoc pipeline (Lab 12)**
Flow вирішив проблему **Unnecessary Tool Calls**. У Лаб 12 агенти викликали інструменти для кожної вакансії підряд (навіть для Sales менеджерів). Завдяки етапу `route`, Flow миттєво відкидає нетехнічні вакансії, суттєво економлячи обчислювальні ресурси LLM. Крім того, архітектура стала стійкою до фатальних помилок (завдяки ізоляції стану).

**10. Де flow був надлишковим**
Для дуже коротких і простих вакансій ("Python dev, 2 роки") багатоступенева перевірка (Validate + Fallback) займала більше інженерного коду, ніж власне виконання задачі, хоча LLM справляється з цим безпомилково.

**11. Що б ви фіксили далі**
Впровадив би динамічний Router. Зараз роутинг базується на примітивному словнику ключових слів. Якщо у тексті є і "Sales", і "Python", роутер може прийняти хибне рішення. Краще використовувати швидку класифікаційну ML-модель для етапу `route`.
