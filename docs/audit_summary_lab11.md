# Audit Summary: Lab 11 (LLM Extraction & Schema-First)

## 1. Task Description
**Домен:** ІТ-вакансії платформи DOU.
**Завдання:** Витягти 6 жорстко типізованих полів (`position`, `skills`, `years_of_experience`, `salary_range`, `work_format`, `english_level`) із сирого неструктурованого тексту вакансій, змішаного з українською та англійською мовами.

## 2. Evaluation Set
* **Кількість текстів:** 15.
* **Особливості:** Тексти містять нестандартні формати грошей ("$4k"), стажу ("від 2 років", "3+ years") та неявні формати роботи ("віддалено", "офіс").

## 3. Metrics Summary
Результати прогону на моделі `gemini-1.5-flash` (з лімітом у 2 repair спроби):

| Метрика | Значення | Опис |
| :--- | :--- | :--- |
| **Raw valid JSON rate** | 100.0% | Модель ідеально формує синтаксис JSON без сміття. |
| **Schema-valid JSON rate** | 0.0% | З першої спроби жоден JSON не пройшов сувору типізацію. |

## 4. Error Analysis & Repair Loop Effectiveness
Аналіз 15 помилок показав такі наймасовіші категорії:

1. **Type Error (Найчастіша):** Модель системно відмовляється повертати чистий `number` для поля `years_of_experience`. Замість очікуваного `3`, вона повертає `"3+"` або `"3 роки"`, що ламає схему.
2. **Enum Error:** Поле `work_format` очікує точний збіг (`remote`, `office`, `hybrid`, `not_specified`). Модель галюцинує регістром (`Remote`) або мовою (`віддалено`).
3. **Null Handling Issue:** Замість `null` для відсутніх полів, модель намагається вставити текст (напр., `"Not specified"`).

**Чому Repair Loop не врятував?**
Repair prompt вказував моделі на помилку типу (напр., *"Schema Error: '3 роки' is not of type 'number'"*). Проте модель, не маючи глибокого розуміння суворої типізації через звичайний промпт, намагалася "виправити" це, повертаючи `"3 years"` або `"three"`, що знову викликало помилку.

## 5. Головний висновок
**Schema-First підхід довів свою цінність як інструмент діагностики.** Він показав, що для суворої типізації недостатньо простого prompt engineering або repair loop. Для вирішення проблеми типізації необхідно використовувати механізми **Structured Outputs** (JSON Schema enforcement на рівні API) або спеціалізований Fine-Tuning.
