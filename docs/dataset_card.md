У межах пайплайну було проведено тестування лінгвістичних ознак (лем та POS-тегів) за допомогою бібліотеки Stanza. 

**Рішення:** 
Відмовитися від використання лематизації для основної задачі Extraction / NER.

**Обґрунтування:** 
1. Агресивна токенізація та лематизація руйнують цілісність специфічних ІТ-сутностей (наприклад, `C++` розпадається на окремі токени, `Node.js` втрачає крапку).
2. Трансліт та сленг (наприклад, `бекенді`, `фіксити`) отримують некоректні леми, що створює додатковий шум.

Дані продовжуватимуть оброблятися у форматі `processed_v2`. Леми можуть бути використані пізніше виключно для повнотекстового пошуку (Retrieval) або кластеризації.

## Еволюція датасету: Information Extraction (Lab 4)
Для збагачення датасету вакансій впроваджено правиловий модуль (Regex + Dictionaries) для витягування структурованої інформації з поля `clean_text`. 
Наразі витягуються 3 типи сутностей:
* `SALARY` (нормалізовано у словник з min/max та валютою)
* `EXPERIENCE_YEARS` (нормалізовано у float)
* `ENGLISH_LEVEL` (нормалізовано до шкали CEFR: A1-C2).
Модуль побудовано за принципом "Precision-first", що гарантує високу точність витягнутих даних завдяки використанню евристичних фільтрів та словників синонімів.
