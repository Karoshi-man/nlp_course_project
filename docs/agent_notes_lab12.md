# Agent Notes Lab 12: Vacancy Assistant

**1. Який use case обрано**
Варіант 3: CV / Vacancy Assistant. Аналіз неструктурованих текстів ІТ-вакансій (наприклад, з платформи DOU).

**2. Який agent task**
Отримання сирого тексту вакансії та автоматичне вилучення двох сутностей: ключового стеку технологій та мінімально необхідних років досвіду роботи.

**3. Які tools реалізовано**
* `extract_technologies`: детермінований пошук мов програмування, фреймворків та баз даних за допомогою заздалегідь підготовленого словника IT-термінів.
* `detect_experience_years`: розпізнавання необхідного досвіду (у роках) за допомогою регулярних виразів (RegEx), які ловлять патерни на кшталт "3+ роки", "від 1 року".

**4. Як агент вирішує, коли викликати tool**
Агент працює за парадигмою ReAct (Reason + Act). У системному промпті йому надано описи інструментів та жорстка вимога повертати відповідь у форматі JSON. Отримуючи вакансію, LLM генерує поле `thought` (думку), де усвідомлює необхідність знайти стек і досвід. Оскільки агент проінструктований не спиратися на власні знання, він формує виклик `tool_name` з необхідними параметрами. Оркестратор виконує функцію і повертає результат агенту для фінального висновку.

**5. Як логуються tool calls**
Реалізовано окремий клас `ToolLogger`. Кожен виклик інструменту (як успішний, так і з помилкою) автоматично перехоплюється і записується у файл `docs/tool_logs_lab12.jsonl` у форматі JSON Lines. Для кожного виклику фіксуються: `timestamp`, `task_id`, `tool_name`, `input`, `output`, `success` (boolean) та текст помилки (якщо є).

**6. Що tools реально покращили**
Інструменти повністю ліквідували галюцинації моделі. Базова LLM (Baseline), якщо не знаходила в тексті досвіду, часто "вигадувала" стандартний 1 рік. Завдяки інструменту `detect_experience_years`, якщо RegEx не знаходив збігів, він повертав `null`, і агент чесно відповідав: "досвід не вказано". Також інструменти ідеально впоралися з конфліктними вимогами (наприклад, "від 1 року, в ідеалі 3+"), спираючись на точні розрахунки масиву.

**7. Де tools були зайві або не допомогли**
Виклики інструментів виявилися зайвими (Unnecessary tool calls) при обробці нетехнічних вакансій (наприклад, Sales Manager) або вакансій-"заманух" (описи про "каву, печиво і дружній колектив"). Агент всліпу викликав екстракцію технологій, витрачаючи час та токени на тексти, де IT-стеку за визначенням бути не могло.

**8. Які помилки лишилися**
* **Сліпота до нових технологій:** Оскільки `extract_technologies` базується на хардкод-словнику, він пропускає специфічні або нові фреймворки (наприклад, інструменти з GameDev чи вузькопрофільні бібліотеки).
* **Відсутність раннього переривання:** Агент не здатний самостійно відмовитися від виклику інструментів, якщо текст очевидно є сміттям.

**9. Що б ви фіксили далі**
1. **Впровадження маршрутизації (Early Exit):** Додати перед екстракторами інструмент-класифікатор `is_tech_vacancy`. Якщо він повертає `false`, агент має миттєво переривати роботу і видавати фінальну відповідь, економлячи ресурси.
2. **Покращення інструменту технологій:** Замість простого словника всередині інструменту `extract_technologies` інтегрувати легковагову NER-модель (наприклад, SpaCy з EntityRuler), щоб витягувати технології більш контекстно.
